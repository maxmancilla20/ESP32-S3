# Project Structure and Drivers

This document describes the ESP-IDF application structure, the local drivers, and the GPIO pins assigned to each peripheral.

## High-level structure

```text
esp_IoT/
├── CMakeLists.txt                 # Project build setup and component search paths
├── dependencies.lock              # Resolved ESP-IDF component versions
├── sdkconfig                      # ESP-IDF project configuration
├── main/
│   ├── main.c                     # Application startup and FreeRTOS tasks
│   ├── CMakeLists.txt             # Registers main.c and its driver dependencies
│   └── idf_component.yml          # Managed component requirements
├── drivers/                       # Project-specific hardware drivers
│   ├── bmp180/
│   ├── buzzer/
│   ├── ir_nec/
│   ├── oled_display/
│   ├── rgb_led/
│   └── st7735_display/
├── esp-idf-lib/                   # External esp-idf-lib components (including DHT)
├── managed_components/            # Components downloaded from the ESP Component Registry
└── build/                         # Generated build output; not application source
```

Each local driver uses this layout:

```text
drivers/<driver>/
├── CMakeLists.txt
├── inc/                           # Public headers included by other components
└── src/                           # Driver implementation
```

## Application flow

`main/main.c` coordinates the drivers:

1. Starts the looping Christmas melody task on the passive buzzer.
2. Initializes the BMP180, ST7735 TFT, OLED, and NEC infrared transceiver.
3. Starts a task that updates the RGB LED every 500 ms.
4. Starts a task that reads the BMP180 and refreshes the TFT every 1,000 ms.
5. Starts a task that reads the DHT11 and refreshes the OLED every 2,000 ms.

The BMP180 and OLED share the I2C bus on GPIO 18 (SDA) and GPIO 19 (SCL). The TFT uses a separate SPI connection.

## Local drivers

| Driver | Location | What it does | GPIO / interface |
|---|---|---|---|
| **BMP180** | `drivers/bmp180/` | Initializes and reads temperature and pressure from the BMP180, then estimates altitude. Its readings are shown on the TFT. | I2C: SDA GPIO 18, SCL GPIO 19; address `0x77`. |
| **Buzzer** | `drivers/buzzer/` | Configures LEDC PWM and runs the Christmas melody in a dedicated repeating FreeRTOS task. | GPIO 13, PWM output. |
| **NEC infrared transceiver** | `drivers/ir_nec/` | Captures IR receiver edges, recognizes NEC frames, provides NEC transmission and last-frame replay APIs, and maps selected received commands to RGB LED colors. | Receiver GPIO 4; transmitter GPIO 5. |
| **OLED display** | `drivers/oled_display/` | Renders DHT11 temperature and humidity, or an error message, on a 128×64 SSD1306-compatible OLED. The display code sends commands and framebuffer data over I2C. | I2C: SDA GPIO 18, SCL GPIO 19; address `0x3C`. |
| **RGB LED** | `drivers/rgb_led/` | Initializes and controls the single onboard WS2812 addressable RGB LED. Used by the periodic LED task and selected IR commands. | GPIO 38; RMT signal for WS2812. |
| **ST7735 display** | `drivers/st7735_display/` | Initializes the 1.8-inch ST7735 TFT and renders BMP180 readings or a sensor error screen. | SPI: SCLK GPIO 12, MOSI GPIO 11, CS GPIO 10, DC GPIO 9, RST GPIO 8; backlight GPIO 7. MISO is not connected. |

## Other components and configuration

- **DHT11 driver:** provided by the external `esp-idf-lib/components/dht` component; the application reads the sensor from GPIO 6.
- **`i2cdev` and helpers:** external `esp-idf-lib` components used for I2C device access and shared bus support.
- **`espressif/led_strip`:** managed ESP-IDF component used by the WS2812 RGB LED driver.
- **`waveshare/esp_lcd_st7735`:** managed component used by the ST7735 display driver.
- **`dependencies.lock`:** pins the resolved managed component versions for repeatable builds.
- **`sdkconfig`:** generated/configured ESP-IDF project settings, including the BMP180 I2C pins.
- **`build/`:** generated compiler and build artifacts. It is not source code and is normally regenerated by the build system.

## Pin and voltage notes

- BMP180 and OLED are on the same I2C bus; connect both devices to GPIO 18/19 and share ground with the ESP32-S3.
- The TFT module's pin labelled `SDA` is SPI MOSI (GPIO 11), not I2C SDA.
- The DHT11 uses a single-wire data signal on GPIO 6.
- The project uses 3.3 V GPIO logic. Do not apply 5 V to ESP32-S3 GPIO pins.
- Confirm the exact development-board/module pinout before using any GPIO not listed above; some pins may be reserved by the board or its flash/PSRAM.

For the logical chip-style pin map and the full list of GPIOs not assigned by the project, see [`doc/ESP32-S3 PinOut.md`](doc/ESP32-S3%20PinOut.md).
